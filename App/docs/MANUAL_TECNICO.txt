1. RESUMEN GENERAL DEL SISTEMA
--------------------------------------------------------------------------------
Nombre del Sistema: SENA PDV (Punto de Venta e Inventarios)
Lenguaje Principal: Python 3.x
Framework de Interfaz Grafica: Flet (basado en Flutter para Python)
Base de Datos: MySQL (Base de datos relacional sena_pdv)
Patron de Arquitectura: Modelo - Vista - Controlador (MVC)

Proposito del Sistema:
El sistema proporciona una solucion integral para el control de operaciones
comerciales en tiempo real:
- Gestion de ventas POS e impresion de facturas/tirillas termicas y archivos PDF.
- Registro de compras e ingreso de mercancia a proveedores.
- Emision de remisiones (despacho/salida de stock).
- Control de inventario en tiempo real con actualizacion automatica de existencias.
- Consulta unificada de documentos y exportacion de reportes consolidados en Excel.
- Gestion de usuarios y control de acceso basado en roles.

3. MODELO DE BASE DE DATOS (ESQUEMA ENTIDAD-RELACION)
--------------------------------------------------------------------------------
Base de Datos: sena_pdv (MySQL)

Tablas y Campos Principales:

1. usuarios:
   - id_usuario (INT, PK, AUTO_INCREMENT)
   - nombre (VARCHAR)
   - usuario (VARCHAR, UNIQUE)
   - password (VARCHAR)
   - rol (VARCHAR) -> ej. "Administrador", "Cajero"

2. clientes:
   - id_cliente (INT, PK, AUTO_INCREMENT)
   - nombre (VARCHAR)
   - documento (VARCHAR)
   - direccion (VARCHAR)
   - telefono (VARCHAR)
   - rol (VARCHAR)

3. proveedores:
   - id_proveedor (INT, PK, AUTO_INCREMENT)
   - nombre (VARCHAR)

4. producto:
   - id_producto (INT, PK, AUTO_INCREMENT)
   - nombre (VARCHAR)
   - unidad (VARCHAR) -> ej. "UND", "KG", "MTR"
   - lugar (VARCHAR) -> Ubicacion fisica en bodega/estante
   - precio (DECIMAL/DOUBLE)
   - stock (DECIMAL/INT) -> Cantidad fisica disponible

5. venta:
   - id_venta (INT, PK, AUTO_INCREMENT)
   - fecha (DATETIME)
   - total (DECIMAL)
   - metodo_pago (VARCHAR) -> ej. "Efectivo", "Transferencia", "Mixto"
   - estado (VARCHAR) -> ej. "ACTIVA", "ANULADA"
   - id_cliente (INT, FK -> clientes.id_cliente)
   - id_usuario (INT, FK -> usuarios.id_usuario)
   - dinero_recibido (DECIMAL)
   - cambio (DECIMAL)
   - notas (TEXT)

6. detalle_venta:
   - id_detalle (INT, PK, AUTO_INCREMENT)
   - id_venta (INT, FK -> venta.id_venta)
   - id_producto (INT, FK -> producto.id_producto)
   - cantidad (DECIMAL)
   - precio_unitario (DECIMAL)
   - subtotal (DECIMAL)

7. compras:
   - id_compra (INT, PK, AUTO_INCREMENT)
   - fecha (DATETIME)
   - total (DECIMAL)
   - id_proveedor (INT, FK -> proveedores.id_proveedor)
   - id_usuario (INT, FK -> usuarios.id_usuario)
   - estado (VARCHAR) -> ej. "ACTIVA", "ANULADA"

8. detalle_compras:
   - id_detalle (INT, PK, AUTO_INCREMENT)
   - id_compra (INT, FK -> compras.id_compra)
   - id_producto (INT, FK -> producto.id_producto)
   - cantidad (DECIMAL)
   - precio_unitario (DECIMAL)
   - subtotal (DECIMAL)

9. remision:
   - id_remision (INT, PK, AUTO_INCREMENT)
   - fecha (DATETIME)
   - tipo_remision (VARCHAR)
   - id_cliente (INT, FK -> clientes.id_cliente)
   - id_usuario (INT, FK -> usuarios.id_usuario)
   - notas (TEXT)
   - estado (VARCHAR)

10. detalle_remision:
    - id_detalle_remision (INT, PK, AUTO_INCREMENT)
    - id_remision (INT, FK -> remision.id_remision)
    - id_producto (INT, FK -> producto.id_producto)
    - cantidad (DECIMAL)


4. FLUJO DE DATOS Y LOGICA DE NEGOCIO PRINCIPAL
--------------------------------------------------------------------------------
A. Modulo de Ventas (POS):
   1. Seleccion de Cliente y Productos mediante modales (buscarCliente, buscarProducto).
   2. Calculo Dinamico: ventasController.py recalcula subtotales y totales.
   3. Registro de Pago: El modal metodoPago.py recibe las formas de pago y liquida el cambio.
   4. Transaccion en Base de Datos (ventasModel.guardar_factura):
      - Inserta el encabezado en 'venta'.
      - Inserta los productos en 'detalle_venta'.
      - Descuenta stock: UPDATE producto SET stock = stock - %s WHERE id_producto = %s
      - Aplica commit() o rollback() en caso de fallo.
   5. Generacion de PDF (ReportLab en generarFactura.py) e impresion termica.

B. Modulo de Compras:
   1. Seleccion de proveedor e ingreso de articulos comprados.
   2. Al guardar (comprasModel.guardar_compra):
      - Inserta compra y detalles (compras, detalle_compras).
      - Incrementa stock: UPDATE producto SET stock = stock + %s WHERE id_producto = %s

C. Modulo de Remisiones:
   1. Movimientos o despachos sin cobro directo.
   2. Descuenta existencias del inventario (remisionesModel.guardar_remision).

D. Modulo Multiventana / Subprocesos Independientes:
   - Permite abrir modulos en ventanas independientes mediante abrirNuevaVentana.py.
   - Lanza un nuevo proceso del script principal (sys.executable App/main.py).
   - Pasa variables de entorno (POS_VIEW, POS_USUARIO) para definir la vista y mantener la sesion.


5. DEPENDENCIAS Y REQUISITOS TECNICOS
--------------------------------------------------------------------------------
Las dependencias requeridas (App/requirements.txt) son:

- flet == 0.85.2                 : Framework GUI para la interfaz visual y reactiva
- mysql_connector_repackaged == 0.3.1 : Driver para comunicacion con MySQL
- reportlab == 4.5.1             : Generacion de facturas e informes en PDF
- python-escpos == 3.0           : Soporte para impresoras termicas POS
- openpyxl == 3.1.5              : Exportacion de reportes estructurados a Excel


6. GUIA DE INSTALACION Y CONFIGURACION PARA GITHUB PASO A PASO
--------------------------------------------------------------------------------
Requisitos Previos:
- Git instalado en el sistema.
- Python 3.10 o superior (verificar con: python --version).
- Servidor MySQL (Laragon, XAMPP, WAMP o MySQL Server) corriendo en el puerto 3306.

Paso 1: Clonar el Repositorio de GitHub
   git clone https://github.com/tu-usuario/tu-repositorio.git
   cd tu-repositorio

Paso 2: Configurar la Base de Datos MySQL
1. Abrir tu gestor de MySQL (phpMyAdmin, HeidiSQL, DBeaver o la consola de Laragon/XAMPP).
2. Importar el archivo sena_pdv.sql (o database.sql).

   NOTA DE PERSONALIZACION / DERECHOS DE AUTOR:
   El nombre de la base de datos es totalmente personalizable para que cualquier usuario o empresa
   que adapte este sistema pueda asignar el nombre que desee.
   Para cambiar el nombre de la base de datos:
   - Cambiar en el script SQL: CREATE DATABASE IF NOT EXISTS nombre_que_elijas; USE nombre_que_elijas;
   - Ajustar la variable DB_NAME en App/database/bd.py o mediante la variable de entorno DB_NAME.

3. Verificar/Ajustar las credenciales en App/database/bd.py:
   DB_HOST = os.getenv("DB_HOST", "localhost")
   DB_USER = os.getenv("DB_USER", "root")
   DB_PASSWORD = os.getenv("DB_PASSWORD", "")
   DB_NAME = os.getenv("DB_NAME", "sena_pdv")

Paso 3: Crear el Entorno Virtual e Instalar Dependencias
En la raiz del proyecto ejecuta:

   # En Windows (PowerShell)
   python -m venv venv
   .\venv\Scripts\Activate.ps1
   pip install -r App/requirements.txt

   # En Linux / macOS
   python3 -m venv venv
   source venv/bin/activate
   pip install -r App/requirements.txt

Paso 4: Ejecutar la Aplicacion
   python App/main.py

Paso 5: Resolucion de Problemas Frecuentes
- Error de conexion a MySQL: Verifica que el servicio de MySQL en Laragon/XAMPP este encendido y que el usuario/contrasena en App/database/bd.py coincidan.
- Error al activar venv en Windows: Si aparece error de politicas de ejecucion en PowerShell, ejecuta: Set-ExecutionPolicy Unrestricted -Scope Process y vuelve a activar.
